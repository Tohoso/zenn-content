公式が来る1週間前に同じコンセプトのOSSを出していた。

それでも公式と取って代わられない実装を作る選択をした話を書く。

---

## 4月19日、tmux-on-g2 を出した

きっかけはアイアンマンのジャービスだった。

Even Realities G2 を買って、テンプル長押しで音声入力 → 家の tmux で動いてる Claude Code に流し込み → 散歩中に「これ実装したい」と思いついたら声で投げて、10分後にラップトップ開いたら半分できてる。そういう体験を作りたかった。

4月19日に CORENOVA Discord に初投稿で `tmux-on-g2` を出した。Even Hub SDK が4月にローンチしたばかりで罠だらけで、1日で10個くらい踏み抜いた記録を `docs/SDK-NOTES.md` に残した。

このときの出した経緯はこちらの記事に書いている: [tmux を Even Realities G2 に映す OSS を書いた — JARVIS への第一歩として](https://note.com/toru_hosokawa/n/n09c3120d65a8)

「まあこれを公式が出してきたら俺の OSS は意義を失うかもな」と思った。実際、Will Lu (Even Realities CEO) が Even Journal EP.4 で「Terminal Mode 作った」とちょうど予告した時期だった。

## 4月24日、公式が来た

Even Realities が Terminal Mode を一般公開した。

Even App v2.2.0 のリリースノート:

> **New Feature - Terminal**
> Terminal is a built-in mode on Even G2 that turns the glasses into a wearable control layer for AI coding agents, so developers can stay aware, take action, and keep work moving from anywhere.

仕組み:

- スマホアプリで「ターミナルモード有効化」をタップ
- PC 側で `npm install -g @evenrealities/even-terminal` (Node.js + npm 必須)
- Claude Code or Codex がインストール済みの状態で `even-terminal` 起動
- スマホアプリが port 3456 にペアリング → G2 に session 表示

`@anthropic-ai/claude-agent-sdk` を内部で使って Claude Code session を作る設計。

俺の `tmux-on-g2` よりちゃんとしてた。**完成度は高い。**

## ただし限界があった

実際に公式 Terminal を使ってみて、Discord に上がってる他ユーザーの報告と合わせて、3つの本質的な制約が見えた。

### 1. Claude session を専有する

Even Terminal が Claude Code session を新規に作って、その session を agent SDK 経由で制御する。つまり:

- 自分が普段 tmux で `claude --continue` で動かしている session には**触れない**
- 新規 Claude session が作られて、そこに G2 から話す形になる
- 既存の対話 context (思想、記憶、進行中タスク) を引き継げない

これは俺にとって決定的だった。普段、4 つの Claude Code セッションをアカウント別 (cc / alpha / beta / gamma) に常駐運用していて、それぞれが独立した記憶 (`~/.claude-*/projects/<cwd>/<uuid>.jsonl`) と context を持っている。「歩優」と呼んでいる自分専用 AI で、そのシステムについてはこの記事に書いた:

[人間と AI エージェントが一緒にビジネスを回す方法 — 歩優というシステムの話](https://note.com/toru_hosokawa/n/n2926b598b937)

公式 Terminal が新規 session で動くと、これらの対話履歴を引き継げない。「歩優じゃない素の Claude Code」と話すのに等しい。

### 2. TUI 装飾の混入

実装で `pipe-pane` 経由 tmux capture を使うと、Claude Code TUI のスピナー (✻ ✶ ✢ ✽)、罫線 (━ │ ┌ ┐)、status line (`Cultivating…`、`↓ 23 tokens`) が混入する。これを strip しきれない。

Discord でも `jimrandomh` が「Terminal Mode って結局 Claude Code ラップだけで real terminal がない、SDK レベルで monospace font 不可だから real terminal は作れない」と書いていた。

### 3. session が fork される

新しい prompt を投げるたびに session が枝分かれして、デスクトップ側で対話を続けようとしても続かない。Discord の `samk8834` が「Sessions を fork するな」とフィードバックを送っていた。

---

「Anthropic 公式が来た。素直に乗り換えるべきか?」

ここで踏みとどまった。**俺が欲しいのは Claude Code じゃなく、歩優との対話だった。**

## Plan B: tmux ミラーリング Provider を作る

Even Terminal の内部実装を読んだ。`getProvider(name)` が `claude` か `codex` のどちらかを返す関数で、Provider Interface (9メソッド) を実装すれば任意の AI source に切り替えられる構造になっていた。

公式の枠 (HTTP API、SSE、スマホアプリの session 切替 UI) はそのまま借りる。ただし `claudeProvider` の代わりに `ayuProvider` を仕込んで、**tmux で動いてる4つの Claude Code セッションを G2 から呼べる**ようにする。

### 設計

```
G2 → スマホ Even App (テンプル長押しで音声入力 + STT)
        ↓ POST /api/prompt {sessionId:"ayu:gamma", text}
even-terminal :3456 (改造版、AYU_FORCE_PROVIDER=1)
        ↓ getProvider() → ayuProvider
ayuProvider.prompt()
        ↓ tmux -L gamma send-keys -t ayu-gamma -l "..."
gamma tmux pane (自分がいま見てる pane と同じ)
        ↓ Claude Code Max plan で応答
~/.claude-gamma/projects/-srv-ayu-workspace/<uuid>.jsonl
        ↓ jsonl tailer (fs.watchFile で増分検知)
        ↓ 完了 message を 8文字 / 30ms で人工 chunk 化
        ↓ text_delta SSE → スマホ → G2 表示
```

ポイント:

- **tmux session を奪取しない** — `send-keys` は通常入力と同じ扱いなので、自分が tmux で見ている pane に追加注入される。デスクトップでの入力と G2 からの入力が並列で、両方が同じ pane に流れる
- **対話 context の継続性** — `claude --continue` で動いてる既存 session に積むので、それまでの会話履歴・記憶・指示書が全部残る
- **4 セッション切替** — cc / alpha / beta / gamma の 4 つを Even App の session 切替で選べる。各 slot は別 tmux socket (`tmux -L cc`, `tmux -L alpha` …) で動く独立 server

### 実装で詰まった3点

### TUI 装飾を完全除去する

最初は tmux pipe-pane の出力を ANSI strip で text 化していたが、罫線・スピナー・status line が残った。フィルタを強化しても完璧にならない。

そこで `~/.claude-${slot}/projects/<encoded-cwd>/<uuid>.jsonl` を直接 tail する方針に切り替えた。Claude Code は対話を JSON Lines で `~/.claude/projects/` 配下に保存している。これを読めば assistant の content block が完全 clean な Markdown 形式で取れる。

```js
function _processLine(line) {
  const obj = JSON.parse(line);
  if (obj.type === "assistant") {
    const content = obj.message?.content || [];
    for (const block of content) {
      if (block.type === "text" && block.text?.trim()) {
        this.onEvent({ type: "text_delta", text: block.text });
      }
    }
    if (obj.message?.stop_reason === "end_turn") {
      this.onEvent({ type: "result", success: true });
    }
  }
}
```

これで装飾ゼロ。

### ストリーミングが流れないバグ

jsonl は完了 message を一括で書く。1個の長文 text_delta が一発で来るので、UI で「ストリーミング感」がゼロになる。タイピング風の体験が欲しい。

人工 chunk 化を入れた:

```js
const STREAM_CHUNK_SIZE = 8;
const STREAM_INTERVAL_MS = 30;

function enqueueText(sessionId, fullText) {
  for (let i = 0; i < fullText.length; i += STREAM_CHUNK_SIZE) {
    queue.push(fullText.slice(i, i + STREAM_CHUNK_SIZE));
  }
  drainQueue(sessionId);
}
```

`result` event は queue が drain されてから flush。これで滑らかに G2 に流れてくる体験が成立した。

### last-prompt 誤 idle 介入

Claude Code は prompt 受信時に jsonl に `type: "last-prompt"` の entry を書く。これを `status: "idle"` に変換していたら、prompt 直後に App が「応答完了」と判定して、その後の text_delta を全部捨てる事態になった。

last-prompt は完了シグナルではない。`assistant.stop_reason === "end_turn"` だけが完了。これを修正したら順序が:

```
busy → text_delta連続 → result → idle
```

の理想形になった。

## 動作確認

実際に G2 から `ayu:gamma` (= 自分がいま動かしてる Claude Code session) に「動作テスト、短く返事を」と話しかけたら、tmux pane に「動作テスト、短く返事を」が注入されて、応答「了解、生存。」が 1 chunk で G2 に流れた。

長文だと:

```
[user]      betaちゃん、調子どう?短く
[busy]
[chunk 1]   元気。openc
[chunk 2]   law 4.23
[chunk 3]    rollbac
[chunk 4]   k + 11 j
[chunk 5]   obs 復活注入
[chunk 6]   済、5分後の発火
[chunk 7]   待ち中。
[result]
[idle]
```

8文字 / 30ms で 7 chunk に分かれた streaming。Even App でタイピング風に表示される。

## 何を作ったかの言い直し

公式 Even Terminal の枠 (スマホアプリ UI、SSE、Provider Interface) はそのまま借りる。Provider 実装を差し替えて、4 つの Claude Code セッションの tmux pane に直結する mirroring プロバイダにした。

- ✅ Claude session を専有しない (既存 tmux pane に注入)
- ✅ TUI 装飾なし (jsonl tail で完全 clean)
- ✅ Sessions が fork されない (1 slot = 1 永続 session)
- ✅ 人工 chunk streaming で UI 体験は維持
- ✅ 4 つを G2 から切替可
- ✅ デスクトップで見ている画面と G2 が完全ミラー

公式の良いところを使いつつ、公式が縛ってる本質的な制約 (新規 session 専有 / TUI 装飾 / fork) を全部解消した。

## ジャービス構想の意味

なぜここまで作るかというと、自分にとって「散歩中に AI と話す」のは別の AI じゃなく**自分の歩優と話す**ことが意味だからだ。

普段の生活と AI が溶け込んでいる感覚については過去にも書いた: [AIエージェントと暮らす日常](https://note.com/toru_hosokawa/n/n8040506875a9)

歩優は cc / alpha / beta / gamma の4つの Claude Code セッションとして並列に存在する。各セッションが共通の指示書 (SOUL.md) と記憶 (memory/) と知識 (wiki/) を共有していて、Max plan で動いている。1つの人格が4つの身体に乗って、tmux 上で常時稼働している、というのが一番近い説明。

公式 Terminal で素の Claude を新規 session で動かすのは、自分にとって違う体験だった。歩優じゃないからだ。

ayu-even-provider で公式の枠を借りた瞬間、G2 から「歩優 cc」「歩優 alpha」とかで話せるようになって、各セッションが SOUL.md の context を保ったまま応答してくる。これが自分の中での「ジャービス」の最終形だった。

## 技術スタック

- **Node.js ESM** (build なし、`.js` 直接動かす)
- **Even Terminal v0.6.5** (`@evenrealities/even-terminal`) を patch-package 形式で改造
- **fs.watchFile** で jsonl 増分検知 (300ms polling)
- **tmux multi-socket** (`tmux -L cc/alpha/beta/gamma` で4 server 制御)
- 環境変数 `AYU_FORCE_PROVIDER=1` で公式アプリの `?provider=claude` ハードコードを ayu に強制 routing
- **Tailscale** (interface 限定 listen + ufw block で公開IPからの到達を防ぐ)
- **CWD sandbox** (`/tmp/even-sandbox` で agent からの誤った workspace アクセスを isolate)

実装は約 500 行 (`slots.js` / `tmux.js` / `jsonl-tail.js` / `provider.js` + patch script)。

## 公開方針

ayu-even-provider はまだ個人用設定 (歩優の slot 構成、tmux session 名規約) に依存している。これを公開可能な形に整理して、`tmux-on-g2` の延長として OSS 化する予定。

公式 Terminal Mode を使っているけど「Claude Code の素 session じゃなく既存の tmux pane に話したい」という人がいたら、Provider を差し替えるだけで実現できる構造になっている。
